# Проверки 0.2.0

23–24 октября 2026. Windows x64, Go 1.26.3, JDK 17, SDK 37, NDK r28c. Устройство: выделенный эмулятор Android x86_64 API 36.1 с официальным YouTube 20.10.41.

## Ядро и сборка

- Go vet и полный набор race-тестов; Linux-проверки GitHub Actions.
- Настоящие IP-пакеты через TUN-эквивалент socketpair: DNS-ответ, ICMP port-unreachable для QUIC, TCP RST до SYN-ACK для неподдерживаемого назначения, сохранение владения FD после остановки.
- Проверки DNS: A/AAAA, ошибочные сообщения, отказ служебным адресам, резерв провайдера в автоматическом режиме и сохранение явно выбранного DNS.
- Ручная стратегия не заменяется автоматически. Низкий битрейт/паузы видеоплеера не вызывают перебор работающих стратегий. Проверяется обнаружение завершившегося native-процесса.
- Сохранены проверки TLS/SNI, CONNECT/SOCKS, выбора стратегий, подписей Ed25519, срока конфигурации и отмены соединений.
- Native/gomobile: arm64-v8a, armeabi-v7a, x86_64. Android debug, release с R8 и lint проходят. Четыре подписанных APK; package `ru.razgon.app`, versionName 0.2.0. Первоначальная сборка имела versionCode 5, исправленные APK — 6.

## На Android

- Production APK установлен обновлением с прежней подписью без удаления данных. Проверены имя приложения, версия и ABI.
- Разрешение VPN выдаётся стандартным системным диалогом. В production allowlist присутствует только UID YouTube; UID плагина и отдельного probe исключены.
- Официальный YouTube загрузил страницу видео и воспроизводил **Big Buck Bunny 60fps 4K — Official Blender Foundation Short Film**: получены видеокадры и состояние PLAYING, росли счётчики HTTPS-трафика. Экран плагина в это время закрыт.
- Debug-probe с отдельным UID проверил HTTPS главной страницы (200), доступность API (405 для тестового GET), превью (200) и generate_204 (204). Результаты сверялись с allowlist и счётчиками, чтобы исключить старый прямой маршрут до запуска TUN.
- Проверено сохранение включения и настроек. После перезагрузки Android при включённом автозапуске foreground-сервис и ciadpi запустились без открытия Activity.
- При отсутствии Wi-Fi и мобильной сети экран показывает ожидание сети, тумблер остаётся включённым, native-движок останавливается, VPN-интерфейс сохраняется. После возврата сети выполняется переподключение.
- В тестовой сети обнаружен случай недоступных адресов одного DNS-провайдера; проверены выбор Cloudflare и автоматический резерв DNS. Финальный production APK подключился с автоматическими стратегией и DNS.
- Ручной выбор стратегии и DNS сохраняется и применяется; проверены светлая/тёмная темы, системные панели, автозапуск и настройка скорости уведомления.
- Плитка быстрых настроек действительно выключает VPN/ciadpi и включает обратно. Остановка не привязана к Activity.
- При завершении основного процесса native-процесс не остаётся работающим. `START_STICKY` запрашивает восстановление у Android; немедленный перезапуск после SIGKILL не гарантируется системой.

## Исправленная сборка 6

24 октября повторно проверен путь официального YouTube через per-app VPN. Исправлены перегрузка DoH при массовом разрешении CDN-имён, выбор резерва для отказавшего API-хоста, ложный успех одного TCP-соединения без TLS и сбросы активного видео служебными запросами. После получения существенных видеоданных сбой контрольного HTTP-запроса больше не перезапускает рабочие соединения.

### Матрица 18 стратегий

Каждая стратегия выбрана вручную, затем очищен временный кэш выделенного AVD и открыт настоящий ролик `YE7VzlLtp-4`. Подтверждение просмотра требует одновременно новых CDN-данных и продвижения доступной шкалы плеера минимум на 12 секунд. Сохранены XML экранов и кадры. Открытие HTML/API и флаг PLAYING сами по себе успехом не считаются.

### Встроенная проверка в production APK

- При принудительно остановленном YouTube: HTML и API доступны, но за 45 секунд приём, передача и видеоданные строго 0. Внутренние контрольные запросы не попадают в статистику YouTube.
- Во время просмотра встроенный отчёт выявил смену стратегии из-за отказа контрольного API. Добавлена отдельная защита активного видеопотока и регрессионный тест этого случая.
- В окончательном подписанном release APK после исправления: страница и API доступны, за 45 секунд получено 2.9 МБ видеоданных, 3.6 МБ входящего трафика, пик 4.7 Мбит/с, **0 смен стратегии**. Ролик продолжал воспроизводиться в обычном YouTube, экран плагина был закрыт.
- Проверены сохранение отчёта после перезапуска процесса/обновления APK, дата результата и экспорт полного текста через стандартное меню Android в локальный QA-приёмник.
- Race-тесты включают массовые DNS-запросы с ограниченными TLS-соединениями, отклонение ранее неработавшего DNS-источника, повтор API через правильный DNS, сохранение видео при отказе проверки и исключение TLS-only соединений из видеоданных. Отмена заблокированного соединения дополнительно повторена 30 раз.
- На AVD выполнен Linux-бинарник пакетного теста: DNS, ICMP для QUIC, TCP RST и владение TUN-дескриптором — PASS. Четыре APK подписаны прежним ключом; debug-экран и тестовый UID отсутствуют в production.

## Границы

24 октября владелец проекта проверил исправленный APK на своём устройстве и подтвердил, что всё работает, после чего разрешил заменить файлы текущего релиза. Отдельный диагностический отчёт этой проверки не получен; точная скорость и условия сети не зафиксированы.

Автоматические проверки на физическом ARM-телефоне и конкретной линии Дом.ру в Нижнем Новгороде здесь не выполнялись. ARM ABI проверены сборкой. Эмулятор использует сеть ПК; его результат не доказывает доступность и скорость на любом операторе. Вход в Google-аккаунт на эмуляторе не выполнялся: плагин использует существующее приложение YouTube и не управляет его данными аккаунта.

Последние автоматические результаты доступны в [Actions](https://github.com/sonjiwu2/youtube-plugin-android/actions), APK — в [Releases](https://github.com/sonjiwu2/youtube-plugin-android/releases).
